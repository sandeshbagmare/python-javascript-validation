01 / The decision

For this priority, start with Tree-sitter.

The requirement was clarified during the study: minimize false alarms on valid JavaScript; some invalid code slipping through is acceptable. Here, “false positive” means flagging valid code as broken, which the tables call a false rejection. This is a low-noise structural screening problem, not a complete ECMAScript-validity gate.

Recommended default: pin tree-sitter==0.26.1 and tree-sitter-javascript==0.25.0. Parse each extracted script and inspect ERROR/MISSING nodes. A clean tree means no structural error found; a recovery error means needs review, not automatic proof the source is invalid. Use the locations for a repair request or review before delivery.

Tree-sitter accepted all 52 valid examples, is fast in this test, supports native Python deployment without Node, and has strong ecosystem adoption. It did not uniquely win false-rejection accuracy: the modern fork, Acorn, esprima2 and Oxc also rejected none of these 52 examples. The recommendation combines the clarified tolerance for misses with deployment and maintenance evidence.

The strongest opposing argument: Acorn and the fork had the same observed false-rejection result while catching far more invalid inputs. If stronger detection matters and a Python-installed embedded engine is acceptable, Acorn is the better-established strict-checking choice on these data. Low false alarms alone do not make Tree-sitter more accurate. Choose Tree-sitter because a lightweight advisory screen is sufficient—not because the benchmark proves it superior.

The misses are not all obscure: Tree-sitter also accepts duplicate declarations, misplaced return, and const x;. It missed 49 of 55 intentionally adversarial invalid examples. That corpus emphasizes early errors and does not estimate how often these occur in your LLM output. If those misses become costly, add strict validation as a separate signal.

Strict-validation alternative: esprima-fork==5.0.0 matched all 107 curated labels, but its repository had 0 stars and 129 last-month PyPI downloads in the snapshot, and deep valid inputs hit resource limits. Acorn has substantially stronger adoption and better depth tolerance in the V8 host, but missed one verified early error. Neither finding changes Tree-sitter’s suitability for the narrower screening requirement.

03 / The strongest counterargument

Tree-sitter is good. Its contract is different.

The JavaScript grammar describes itself as a “close approximation” of ECMAScript and deliberately includes JSX. Tree-sitter is designed for incremental parsing, recovery and useful syntax trees even when a document is incomplete. Those are valuable capabilities. They do not imply full lexical, scope or early-error validation.

let x; let x;              // duplicate lexical binding
break;                    // no loop or switch
const view = <div/>;      // JSX, not native browser JavaScript
const r = /a/gg;           // duplicate regex flags

Checking root_node.has_error catches recovery errors; examining both ERROR and MISSING nodes improves diagnostics. Neither supplies missing ECMAScript rules. Small checks can reject JSX or misplaced imports, but complete validation also requires lexical scopes, strictness, labels, private-name environments and ECMAScript-specific regex grammar. That is a substantial validator implementation, not a handful of reliable patches.

The test reveals gaps against a strict validity gate, but that is stronger than the clarified requirement. It is not a ranking of parser quality: we did not measure incremental editing, recovery quality or diagnostic usefulness. Tree-sitter’s strongest role is a fast structural screen. A strict validator is optional when missed early errors are acceptable. If grammar lag produces an error on valid modern syntax, treat it as reviewable rather than adding an unconditional rejection rule.

Why the other contenders fall short

  • Original Esprima 4.0.1: ES2017-era coverage rejects common modern output. Do not confuse it with the newer distributions.
  • esprima2 6.0.0: broad modern syntax acceptance, but observed scope/context early-error gaps.
  • oxc-python 0.1.1: extremely fast, but the inspected binding calls the parser without Oxc’s semantic early-error pass. This finding is about that binding, not Oxc core.
  • Custom Oxc binding: a credible future path if it exposes the parser, semantic syntax checks, regex validation and correct source goals. Not implemented or benchmarked here.
  • QuickJS compile-only bindings: potentially viable, but API exposure, engine editions and module-resolution behavior must be qualified. The tested QuickJS configuration runs trusted Acorn, not submitted programs.
  • SWC Python bindings: researched, not measured; available wrappers have age, platform and parse-goal/API limitations.
  • Babel/Meriyah: researched, not measured. They can run in embedded engines, but require different packaging/options and careful regex-validation qualification.
  • Regex/bracket checks or new Function(source): not equivalent validators. Function-body parsing changes the grammar and accepts top-level return.

05 / The practical pipeline

Extract accurately. Validate in the right context.

  1. Extract each script separately. Keep your BeautifulSoup workflow, with an HTML5-compatible backend where browser tokenization matters. Do not concatenate blocks or HTML-unescape script text.
  2. Classify before parsing. Classic JavaScript uses Script; type="module" uses Module. JSON/JSON-LD uses a JSON parser. Import maps and speculation rules need JSON plus their own structural rules. Unknown data blocks are not automatically JavaScript.
  3. Track coverage. A src attribute means external source is unchecked unless supplied separately; its inline text is not fallback code. Inert template/noscript content and event-handler attributes need deliberate treatment.
  4. Run the structural screen. Preserve no-structural-error, needs-review and inconclusive outcomes. Feed localized diagnostics back to the LLM, then screen the regenerated complete source again. Optional strict checks should be a separate signal, not an unexplained reason to reject otherwise accepted output.
  5. Keep acceptance narrow. “Syntax checked” does not mean the DOM exists, imports resolve, the browser supports every feature, or the page renders correctly.

Minimal tested Python example

python -m pip install tree-sitter==0.26.1 tree-sitter-javascript==0.25.0

These pinned packages require Python ≥3.10 and compatible native wheels. This helper accepts one already-extracted JavaScript source unit. It deliberately does not enforce Script/Module early errors; it is not a whole-page HTML classifier or a hardened service. Give each concurrent worker its own parser.

"""Low-noise structural screening, not complete ECMAScript validation."""
from tree_sitter import Language, Parser
import tree_sitter_javascript


class JavaScriptScreen:
    def __init__(self):
        self.parser = Parser(Language(tree_sitter_javascript.language()))

    def check(self, source: str) -> dict:
        if len(source.encode("utf-8")) > 256_000:
            return {"status": "inconclusive", "reason": "input_size_limit"}
        tree = self.parser.parse(source.encode("utf-8"))
        if not tree.root_node.has_error:
            return {"status": "no_structural_error_found", "issues": []}
        issues = []
        pending = [tree.root_node]
        while pending and len(issues) < 20:
            node = pending.pop()
            if node.is_error or node.is_missing:
                issues.append({
                    "kind": "missing" if node.is_missing else "error",
                    "node_type": node.type,
                    "line": node.start_point.row + 1,
                    "byte_column": node.start_point.column,
                })
            # Include unnamed children: missing punctuation may be anonymous.
            pending.extend(reversed(node.children))
        return {"status": "needs_review", "issues": issues}

The 256,000-byte cap is an example product policy, not a language rule or benchmark-derived optimum. Unexpected infrastructure failures should become service-level inconclusive results, not invalid-source diagnoses. Use worker deadlines rather than interpreting resource exhaustion as malformed source. Columns in this snippet count UTF-8 bytes, not Python characters or JavaScript UTF-16 units.

Optional stricter validator: tested esprima-fork helper

Install esprima-fork==5.0.0 in a fresh environment (Python ≥3.11). Original esprima, esprima2 and this fork all share the esprima import namespace: do not co-install them. This helper uses explicit ES2025 and Script/Module goals, and separates resource limits from syntax errors.

"""Article snippet: validate one already-extracted JavaScript source unit."""
import esprima


def validate_javascript(source: str, mode: str = "script") -> dict:
    if mode not in ("script", "module"):
        raise ValueError("mode must be 'script' or 'module'")
    if len(source.encode("utf-8")) > 256_000:
        return {"status": "inconclusive", "reason": "input_size_limit"}
    parse = esprima.parseModule if mode == "module" else esprima.parseScript
    try:
        parse(source, {"ecmaVersion": 2025, "tolerant": False, "jsx": False})
    except esprima.error_handler.Error as exc:
        message = str(exc)
        # Pinned 5.0.0 reports resource exhaustion with its parser Error class.
        if "nesting exceeds the" in message and "resource limit" in message:
            return {"status": "inconclusive", "reason": "resource_limit"}
        return {"status": "invalid", "diagnostic": message}
    except RecursionError:
        return {"status": "inconclusive", "reason": "resource_limit"}
    return {"status": "valid"}

HTML boundaries that a JavaScript parser cannot repair

<script>const s = "</script>";</script>

The first closing tag terminates the script in ordinary HTML script-data state, even inside a JavaScript string. Worse, a closing tag inside a line comment can leave a syntactically valid truncated script. If you retain the intended script before embedding, compare it with the extracted representation. Do not claim a parser can always reconstruct the LLM’s intention from final HTML.

Script text preserves &amp; literally; event-handler attributes decode character references. For JSON, Python’s default json.loads accepts nonstandard NaN/Infinity: supply a rejecting parse_constant callback for strict JSON. JSON syntax alone does not validate an import-map schema.

Our ten local extraction/JSON checks cover entities, normal/case-varied end tags, escaped closing-tag content, comment truncation, independent blocks, JSON, external-src detection and decoded handler attributes. They are not a complete browser extraction suite. html5lib’s default scripting model affects noscript; template content, namespaces, XHTML, fragments and srcdoc require explicit scope. Handler return false is valid in its own context but invalid at Script top level.

06 / How the arena worked

Independent proposals, shared evidence, adversarial review.

Five initial researchers completed competing proposals: a broad parser comparison, adversarial validity review, native-parser approach, Tree-sitter defense, and an embedded-parser approach. An engine-only researcher failed with a service outage. Later independent contexts challenged labels and scopes, audited the harness, checked the Acorn counterexample against the specification, assessed popularity and defended Tree-sitter. Some additional dispatches failed; failed agents contributed no evidence.

All agents used the same underlying model family. This is independent-context review, not independent-model consensus. No “100-agent” claim is made. Proposals were judged by false acceptance, false rejection, context fidelity, Python deployment, diagnostics and maintenance; no majority vote or star-count vote selected the winner.

The first 82 cases were followed by 25 independently designed valid/invalid challenges. Auditors corrected edition alignment, conflicting Esprima installations, resource-limit classification and timing provenance. The resulting 107-case corpus is curated and diagnostic, not random, blinded, or representative of production frequency. It is not a full Test262 run. Upstream claims about thousands of conformance tests remain upstream claims.

Synthesis after requirement clarification: choose Tree-sitter as the primary structural screen, and retain HTML classification, explicit resource outcomes and honest coverage reporting from the other proposals. The fork wins strict coverage on this corpus but is optional under the user's low-false-alarm priority. Preserve Acorn as an established-ecosystem strict alternative. Original Esprima's 18 false rejections make it a poor fit for this priority. No tested contender has proven a production false-positive rate.

"""Measured parser comparison. Submitted source is passed as data, never run."""
import argparse
from datetime import datetime, timezone
import hashlib
import importlib.metadata
import json
from pathlib import Path
import platform
import statistics
import sys
import time

ROOT = Path(__file__).parent
WRAPPER = """
function validateSource(source, mode) {
  try {
    acorn.parse(source, {ecmaVersion: 2025, sourceType: mode});
    return {status: "valid"};
  } catch (e) {
    if (!(e instanceof SyntaxError)) throw e;
    if (e.message.startsWith("Not enough stack space to parse input")) {
      return {status: "resource_limit", diagnostic: e.message};
    }
    return {status: "invalid", diagnostic: e.message,
            line: e.loc.line, column: e.loc.column};
  }
}
"""


def adapter(name):
    if name in ("esprima", "esprima2", "esprima-fork"):
        import esprima
        options = {"tolerant": False, "jsx": False}
        if name == "esprima-fork":
            options["ecmaVersion"] = 2025
        def check(source, mode):
            try:
                method = esprima.parseModule if mode == "module" else esprima.parseScript
                method(source, options)
                return {"status": "valid"}
            except esprima.error_handler.Error as exc:
                if name == "esprima-fork" and "nesting exceeds the" in str(exc) and "resource limit" in str(exc):
                    return {"status": "resource_limit", "diagnostic": str(exc)}
                return {"status": "invalid", "diagnostic": str(exc)}
        return check, None
    if name == "tree-sitter":
        from tree_sitter import Language, Parser
        import tree_sitter_javascript
        parser = Parser(Language(tree_sitter_javascript.language()))
        def check(source, mode):
            tree = parser.parse(source.encode("utf-8"))
            return {"status": "invalid" if tree.root_node.has_error else "valid"}
        return check, None
    if name == "oxc-python":
        import oxc_python
        def check(source, mode):
            result = oxc_python.parse(source, source_type=mode)
            if result.panicked and not result.errors:
                return {"status": "validator_failure", "diagnostic": "Oxc parser panicked"}
            return {"status": "invalid" if result.errors else "valid"}
        return check, None
    if name == "acorn-v8":
        from py_mini_racer import MiniRacer
        context = MiniRacer()
        context.eval((ROOT / "acorn.js").read_text(encoding="utf-8"))
        context.eval(WRAPPER)
        return lambda source, mode: context.call("validateSource", source, mode, timeout=2000), context
    if name == "acorn-quickjs":
        import quickjs
        context = quickjs.Context()
        context.set_memory_limit(128 * 1024 * 1024)
        context.set_time_limit(2)
        context.eval((ROOT / "acorn.js").read_text(encoding="utf-8"))
        context.eval(WRAPPER)
        call = context.get("validateSource")
        return lambda source, mode: json.loads(call(source, mode).json()), None
    raise ValueError(name)


def main():
    cli = argparse.ArgumentParser()
    cli.add_argument("candidate")
    args = cli.parse_args()
    cases = json.loads((ROOT / "cases.json").read_text(encoding="utf-8"))
    for extra in sorted(ROOT.glob("challenge-*.json")):
        cases.extend(json.loads(extra.read_text(encoding="utf-8")))
    assert len({case[0] for case in cases}) == len(cases), "Duplicate case IDs"
    result = {
        "candidate": args.candidate, "python": platform.python_version(),
        "platform": platform.platform(), "ecmascript_contract": 2025,
        "cases_sha256": hashlib.sha256(json.dumps(cases, ensure_ascii=False).encode()).hexdigest(),
        "case_count": len(cases),
        "timestamp_utc": datetime.now(timezone.utc).isoformat(),
        "benchmark_sha256": hashlib.sha256(Path(__file__).read_bytes()).hexdigest(),
        "acorn_sha256": hashlib.sha256((ROOT / "acorn.js").read_bytes()).hexdigest(),
        "acorn_version": "8.19.0",
        "edition_selection": "explicit 2025" if args.candidate in ("esprima-fork", "acorn-v8", "acorn-quickjs") else "not selected; package default grammar",
        "executable": sys.executable,
        "versions": {d.metadata["Name"]: d.version for d in importlib.metadata.distributions()},
    }
    resource = None
    try:
        check, resource = adapter(args.candidate)
    except Exception as exc:
        result.update(status="unavailable", reason=f"{type(exc).__name__}: {exc}")
    else:
        rows = []
        for case_id, mode, expected, group, source in cases:
            try:
                actual = check(source, mode)
            except Exception as exc:
                actual = {"status": "validator_failure", "diagnostic": f"{type(exc).__name__}: {exc}"}
            rows.append(dict(id=case_id, mode=mode, expected=expected, group=group, **actual))
        # Warm, tiny-source latency includes the binding and verdict conversion, not setup.
        durations = []
        timing_failure = None
        for _ in range(5):
            start = time.perf_counter_ns()
            attempts = 0
            for row, case in zip(rows, cases):
                if row["status"] in ("valid", "invalid"):
                    try:
                        check(case[4], case[1])
                        attempts += 1
                    except Exception as exc:
                        timing_failure = f"{type(exc).__name__}: {exc}"
            if attempts:
                durations.append((time.perf_counter_ns() - start) / attempts / 1000)
        resource_probes = []
        for depth in (32, 100, 300):
            try:
                probe = check("(" * depth + "0" + ")" * depth + ";", "script")
            except Exception as exc:
                probe = {"status": "validator_failure", "diagnostic": f"{type(exc).__name__}: {exc}"}
            resource_probes.append({"depth": depth, "expected": True, **probe})
        result.update(
            status="measured", cases=rows,
            false_accepts=[r["id"] for r in rows if not r["expected"] and r["status"] == "valid"],
            false_rejects=[r["id"] for r in rows if r["expected"] and r["status"] == "invalid"],
            failures=[r["id"] for r in rows if r["status"] == "validator_failure"],
            inconclusive=[r["id"] for r in rows if r["status"] not in ("valid", "invalid")],
            resource_probes=resource_probes,
            timing_failure=timing_failure,
            timed_case_count=sum(r["status"] in ("valid", "invalid") for r in rows),
            warm_microseconds_per_case_median=statistics.median(durations) if durations else None,
        )
    finally:
        if resource is not None:
            resource.close()
    path = ROOT / f"results-{args.candidate}.json"
    path.write_text(json.dumps(result, indent=2), encoding="utf-8")
    print(json.dumps({k: v for k, v in result.items() if k not in ("cases", "versions")}, indent=2))


if __name__ == "__main__":
    main()
